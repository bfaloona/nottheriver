## 1. Rules

- RULE-1. One stretch, one checklist. A stretch is one run's block, ending in its gate where one exists (B1 and B2; B3 to B6; C1 to C5; D1 to D3; D4 and D5). The plan's `## Status checklist` (the `docs/plans/store-types.md:5-13` shape, which `/implement-plan` reads, `~/.claude/skills/implement-plan/SKILL.md:14`) holds only the current stretch's `- [ ]` items; the next stretch's block is written in at the gate ruling or phase end (RULE-6). This is what stops a run: the skill itself runs every unticked item in order and knows nothing of phases or gates (SKILL.md Step 3).
- RULE-2. Scope is the item's named paths. A run may only touch paths a checklist item names (plus tests and docs for those paths). Anything else found on the way is parked, not fixed.
- RULE-3. Parking: one row at the bottom of `docs/STATUS.md` Priorities with a proposed position and a one-line next step (the rule at `docs/STATUS.md:41`), or a `docs/debt.md` row when it is a limitation, not work. Exception: a finding that makes the current item wrong (a test it needs is broken, a cited line moved) is fixed in the same commit if it stays inside RULE-2's paths; otherwise the run halts at the last green commit and asks.
- RULE-4. Gates are the stretch's last checklist item, written `[gate] <name>: operator reads <path>`. The agent ticks it only by reporting the path and adding a row to `docs/STATUS.md` "Blocked on operator" (gate, what it unblocks). Work resumes only when the ruling is written into the plan's "Operator rulings" section or the named evidence file, so the next session can see it without chat history.
- RULE-5. A push or deploy is never a run item. It happens outside the run under `.claude/skills/deploy/SKILL.md`, after a stretch (B7, D3's Worker deploy, D6) or at a gate ruling (C5 rollback), and is ticked by hand: `/implement-plan` never pushes (SKILL.md:99) and `infra/deploy.sh` refuses unpushed commits (deploy SKILL.md:37). Deploy items stay out of the checklist the skill reads, or the next invocation would try to run them. The test bar is the deploy skill's (deploy SKILL.md:12).
- RULE-6. "Done" for a phase: every item ticked, the closing item's evidence recorded (deploy commit and one live search in the session note, deploy SKILL.md:49; or the report path for Phase C), the next stretch's block written into the checklist, and `docs/STATUS.md` updated once: the phase's Priorities row moves to Done, the next row's "Next step" is rewritten, "In flight" names the next phase. No other STATUS edits during a run except parked rows (RULE-3) and the gate row (RULE-4).
- RULE-7. One stretch per session; the session note mirrors the checklist state after every tick (`/private/tmp` scratchpads are lost in a crash; keep the note in the session directory).
